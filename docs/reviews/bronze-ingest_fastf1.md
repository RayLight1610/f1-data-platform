# Review: src/f1_platform/bronze/ingest_fastf1.py

## BLOCKER
- `src/f1_platform/bronze/ingest_fastf1.py:178-181` — `ingest_season` calls `ingest_race_laps/results/weather/telemetry`, each independently calling `load_session` → `session.load()` (lines 59, 87, 115, 143). A single race session is fully reloaded 4 times, multiplying Jolpica API calls ~4x against the stated ~200 req/hour budget and defeating the resume-after-failure design. → Load the session once per event in `ingest_season`, pass the `session` object into each `ingest_race_*` function.
- `src/f1_platform/bronze/ingest_fastf1.py:29-48,53,74-75` — `already_ingested` (separate connection) and the `to_sql` write (separate engine/connection) are not in one transaction. Two concurrent runs, or a rerun that races a still-committing prior run, both pass the check before either writes → duplicate rows, since there is no unique constraint on `(year, event)` and no `ON CONFLICT`. → Enforce a unique constraint on `(year, event[, driver/lap])` and use an upsert (`INSERT ... ON CONFLICT DO NOTHING`) inside one transaction instead of an app-level SELECT-then-INSERT.
- `src/f1_platform/bronze/ingest_fastf1.py:51,75,79,103,107,131,135,169` — `mode` is a free parameter forwarded straight to `to_sql(if_exists=mode)`. `if_exists="replace"` drops and recreates the **whole** table, not just the target year/event slice — any caller passing `mode="replace"` silently deletes all prior seasons' bronze data. → Disallow `"replace"` here; if a slice needs re-loading, `DELETE FROM bronze.<table> WHERE year=... AND event=...` then insert, in one transaction.
- `src/f1_platform/bronze/ingest_fastf1.py:148-153` — `session.laps.pick_fastest()` returns an empty `Laps` object when no lap is valid (red-flagged race, every driver DNF on lap 1, all laps deleted). The next line, `fastest_lap["Driver"]`, then raises on an empty Series — uncaught (only `load_session` is wrapped in try/except), crashing `ingest_race_telemetry` on a realistic input. → Check `fastest_lap.empty` and log-and-return before accessing fields.
- `src/f1_platform/bronze/ingest_fastf1.py:25` — `add_metadata_columns` stamps `datetime.now()` (naive, server-local) as `ingested_at`. Combined with no explicit DDL, pandas/SQLAlchemy will infer a naive `timestamp` column type on first `to_sql` call, contradicting the "all timestamps stored as timestamptz UTC" rule and silently corrupting the ingestion-time metadata if the host isn't UTC. → Use `datetime.now(timezone.utc)` and predefine bronze DDL with `timestamptz`.
- `src/f1_platform/bronze/ingest_fastf1.py:75,103,131,169` — There is no bronze DDL; each table's schema is whatever pandas infers from the first `to_sql(if_exists="append")` call. FastF1's laps/telemetry/results columns are known to vary by season/version (e.g. newer fields absent in older years). The first ingested event fixes the schema; a later event with an extra or missing column will fail the append (crash mid-season, leaving earlier events committed and later ones missing) or silently misalign columns. → Define explicit `CREATE TABLE bronze.raw_*` DDL with the known/expected columns and reindex each DataFrame to that column set before `to_sql`.

## WARNING
- `src/f1_platform/bronze/ingest_fastf1.py:60-62,88-90,116-118,144-146` — Bare `except Exception` around `load_session` swallows 429/rate-limit and network errors identically to "no data for this session," logs, and moves straight to the next event with no backoff. On a real rate-limit hit this burns through the remaining event loop with repeated immediate failures. → Distinguish rate-limit/network errors from data errors; on rate-limit, sleep with backoff or abort the season loop instead of continuing.
- `src/f1_platform/bronze/ingest_fastf1.py:53,74` (and equivalents at 81/102, 109/130, 137/168) — `get_engine()` is called twice per function (once for the idempotency check, once for the write), and again per event in a season loop, each call doing a fresh `create_engine(...)`. Engines/pools are never disposed (`connection.py:18`). → Create one engine per run (or cache/reuse it) and call `engine.dispose()` when done.
- `src/f1_platform/bronze/ingest_fastf1.py:176-184` — The `try/except` around the four `ingest_race_*` calls in `ingest_season` is effectively dead code for the common failure path, since each callee already catches and swallows its own `load_session` exception and returns `None`. It also logs the raw `event` Series (`{event}`) rather than `event["EventName"]`, producing noisy/misleading log lines if it ever does fire. → Remove the redundant outer try/except or give it a distinct purpose; log `event['EventName']` explicitly.
- `src/f1_platform/bronze/ingest_fastf1.py:11` — `fastf1.Cache.enable_cache("./cache")` runs at import time with a path relative to the process's current working directory, and CLAUDE.md forbids editing files under `cache/` but this creates/depends on it as a side effect of merely importing the module. → Make the cache path configurable (env/config) and initialize it lazily inside a setup function, not at module import.
- `src/f1_platform/bronze/ingest_fastf1.py:45` — Table name is interpolated into the SQL string via f-string (`f"SELECT 1 FROM bronze.{table} ..."`) rather than parameterized/whitelisted; harmless today since callers pass hardcoded literals, but the pattern is unsafe if `table` ever becomes derived from external input. → Use a fixed mapping of allowed table names or `sqlalchemy.sql.quoted_name`.

## NIT
- `src/f1_platform/bronze/ingest_fastf1.py:45` — Inconsistent SQL keyword casing (`where` lowercase amid otherwise-uppercase style elsewhere in the query) — purely cosmetic, flagging for consistency.

## VERDICT: FAIL
Redundant 4x session loading burns the rate-limited API budget, and check-then-write has no transactional/uniqueness guarantee — both violate the stated idempotent/atomic and resume-after-failure requirements.
